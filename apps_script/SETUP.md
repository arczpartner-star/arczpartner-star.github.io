# 상담 신청 → 구글 스프레드시트 연결 (상세판 · 2026.10.26)

```
홈페이지 폼 ──▶ Apps Script 웹 앱(/exec) ──▶ 스프레드시트 '상담신청' 시트
                                       └──▶ 알림 메일
```

## 0. 먼저 지금 상태 확인 (1분)

1. 주소창에 `config.js`에 넣은 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)를 **시크릿 창**에서 엽니다.
2. 나오는 화면으로 원인이 갈립니다.

| 화면 | 뜻 | 할 일 |
|---|---|---|
| `{"ok":true,"service":"arcz-lead","version":"2026-10-26","spreadsheet":"…","sheet":"상담신청",…}` | 정상 | 6단계(홈페이지 시험)로 |
| `{"ok":true,"service":"arcz-lead","time":"…"}` (version 없음) | 옛 코드가 배포됨 | 2단계부터 — 새 Code.gs로 바꾸고 **새 버전 배포** |
| `{"ok":false,…"스프레드시트에 연결되지 않았습니다"}` | 스크립트가 시트에 붙어 있지 않음 | 1단계부터 다시(시트에서 Apps Script 열기) |
| 구글 로그인 화면 / “액세스 권한이 필요합니다” | 액세스가 ‘모든 사용자’가 아님 | 5단계 — 배포 설정 바꾸기 |
| “스크립트 함수를 찾을 수 없습니다: doGet” | 코드가 저장·배포되지 않음 | 2~5단계 |
| “페이지를 찾을 수 없습니다” | 주소가 틀림(`/dev`, 잘린 주소) | 5단계의 웹 앱 URL을 다시 복사 |

## 1. 스프레드시트에서 Apps Script 열기

1. 아크즈 구글 계정으로 로그인 → 상담 시트(없으면 sheets.new로 새로 만들고 이름 `ARCZ 상담 신청`)
2. **시트 화면 위쪽 메뉴 → 확장 프로그램 → Apps Script**
   - ⚠ script.google.com에서 ‘새 프로젝트’로 만든 스크립트는 시트에 연결되지 않습니다. 반드시 시트 안의 메뉴로 여세요.
   - 여러 구글 계정에 로그인되어 있으면 다른 계정으로 열릴 수 있습니다. 시크릿 창에서 아크즈 계정 하나로만 로그인해 진행하면 안전합니다.

## 2. 코드 붙여넣기

1. 왼쪽 `Code.gs`의 내용을 **전부 지우고**, 이 폴더의 `Code.gs` 전체를 붙여넣기
2. 맨 위 `NOTIFY_EMAILS`에 알림 받을 메일 확인
3. **💾 저장(Ctrl+S)** — 저장하지 않으면 배포에 반영되지 않습니다.

## 3. setup 실행 + 권한 허용

1. 위쪽 함수 선택 칸에서 `setup` → **▶ 실행**
2. 권한 검토 → 아크즈 계정 선택 → “Google에서 확인하지 않은 앱” → **고급 → (프로젝트 이름)(으)로 이동 → 허용**
3. 시트에 보라색 머리글 13칸이 생기면 성공

## 4. 편집기에서 시험 접수 (testPost)

1. 함수 선택 칸에서 `testPost` → **▶ 실행**
2. 아래 실행 로그에 `{"ok":true}` → 시트에 ‘테스트(지워 주세요)’ 줄 + 알림 메일 1통
   - `{"ok":false,…"detail":"…"}`가 나오면 detail 문구가 원인입니다.
3. 여기까지 되면 시트·메일 쪽은 정상입니다. 테스트 줄은 지워 주세요.

## 5. 웹 앱 배포 (가장 많이 틀리는 곳)

**처음 배포라면:** 오른쪽 위 **배포 → 새 배포 → ⚙ 유형: 웹 앱**

**이미 배포했다면(주소 유지):** **배포 → 배포 관리 → 연필(수정) → 버전: ‘새 버전’ → 배포**
- 코드를 바꾸고 이 과정을 안 하면 예전 코드가 계속 돌아갑니다.

설정값은 정확히 이렇게:
- 실행 사용자(Execute as): **나(아크즈 계정 메일)**
- 액세스 권한이 있는 사용자(Who has access): **모든 사용자(Anyone)**
  - ‘Google 계정이 있는 모든 사용자’가 **아닙니다**. 이걸 고르면 방문자 브라우저가 로그인 화면을 받아 전송이 실패합니다.
  - 목록에 ‘모든 사용자’가 없으면 회사(워크스페이스) 계정이라 외부 공유가 막힌 경우입니다 → 개인 Gmail로 만들거나 관리자에게 요청

배포 후 나오는 **웹 앱 URL**(`…/exec`)을 복사합니다. ‘새 배포’를 다시 누르면 주소가 바뀌니, 그때는 `config.js`도 바꿔야 합니다.

## 6. 홈페이지에서 시험

1. `config.js`의 `leadEndpoint` 주소가 5단계 주소와 **글자 하나까지 같은지** 확인(끝이 `/exec`)
2. `arcz.kr/contact.html?debug` 로 접속해 시험 신청
   - 성공: “진단 신청이 접수되었습니다” + 시트에 한 줄
   - 실패: 빨간 글씨 아래 **원인:** 이 나옵니다.

| 원인 문구 | 할 일 |
|---|---|
| `JSON이 아닌 응답(로그인 화면…)` | 5단계 액세스를 ‘모든 사용자’로 → 새 버전 배포 |
| `요청 실패(Failed to fetch)` | 주소 오타·`/dev` 주소 사용·광고 차단 확장 프로그램 확인 |
| `스프레드시트에 연결되지 않았습니다` | 1단계(시트 메뉴에서 열기) 또는 `CONFIG.SPREADSHEET_ID` 입력 |
| `config.js leadEndpoint = ""` | config.js에 주소가 비어 있음 / 옛 config.js가 올라가 있음 |
| 원인 없이 “개인정보 … 동의” | 동의 체크 누락(정상 동작) |

## 매일 쓰는 법

같은 번호로 2분 안에 다시 보내면 한 번만 저장됩니다(시험할 때는 번호를 바꿔 가며).
